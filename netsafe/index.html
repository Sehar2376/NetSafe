The purpose of this project

What is NetSafe for?

The problem

Every day people get fake bank SMS messages, suspicious links and unfamiliar Wi-Fi networks. Words like OTP, HTTPS or WPA2 are confusing, so many people simply guess, and guessing wrong can cost money or accounts.

Our objective

Help ordinary people make a safer decision in four everyday situations: understand the warning signs in plain English, and know exactly what to do next, even if they already clicked or replied.

Who it is for

Anyone who uses the internet: students, families, shop owners. No technical knowledge needed. Everything runs on your own device, and nothing you type is stored or sent.

After using NetSafe you can:

  • Tell whether a message, link, password or Wi-Fi network deserves your trust, and why.
  • Spot the specific warning signs that scammers rely on.
  • Know what to do right now, including what to do if you already clicked or replied.
  • Understand the security ideas behind it (encryption, HTTPS, WPA3) through hands-on demos.

    Classic vs modern encryption

    Classic ciphers (Caesar, Vigenere, Playfair) use small key spaces and keep letter patterns visible. They fall to brute force and frequency analysis, quickly with a computer.

    Modern encryption (AES in WPA2/WPA3, TLS in HTTPS) uses public, heavily tested algorithms with large keys. Security comes from the key, not a secret method (Kerckhoffs's principle). WPA2 derives its key from your password with PBKDF2 hashing, and WPA3 uses SAE, a password-based key exchange. Either way, a weak or widely shared password weakens protection.

    See real encryption and hashing run in your browser.

    Cryptography Lab

    1. A classic cipher: Caesar

    Educational demo only. Classical ciphers must never be used to protect real data or Wi-Fi.

    

    Only 25 possible keys exist, so an attacker simply tries them all. AES-256 has about 1.2 x 10^77 possible keys.
    


    2. Real encryption: AES-GCM
    

    This uses the same kind of encryption as HTTPS and WPA3 (AES with a key you choose through a passphrase). It runs in your browser with the Web Crypto API. Nothing is stored or sent. It is a learning demo, not a tool for protecting real secrets. Use made-up text.
    



    


    

    

    What happens: your passphrase is turned into a 256-bit key (PBKDF2, 600,000 rounds). A random salt and random nonce are added, so encrypting the same message twice gives different output. AES-GCM then encrypts the message and adds an authentication tag. If the passphrase is wrong, or even one character changes, decryption fails instead of giving wrong output. That is integrity protection.
    


    3. Hashing: SHA-256
    

    A hash is a fixed-size fingerprint of data. It cannot be turned back into the original. The same input always gives the same hash.
    


    SHA-256 of your text
    

    SHA-256 of the same text plus one full stop
    

    

    Notice how a tiny change gives a completely different hash. This is how hashes reveal that a file was changed. Plain SHA-256 is not suitable for storing passwords because it is very fast to guess against. Services use slow, salted methods such as bcrypt, scrypt, Argon2 or PBKDF2.

    Why every account needs its own password
    When a website is breached, attackers try the leaked email and password on other sites. If you reused it, one breach opens many accounts.
    

    Why multi-factor authentication matters
    A second step (an authenticator app or security key) stops a stolen password from being enough. Never share these codes with anyone.
    

    An easier way
    Use a long passphrase for the few passwords you must remember, and a reputable password manager for the rest.
