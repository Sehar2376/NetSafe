# NetSafe fix report (22 November 2026)

## Audit summary

Every HTML, CSS and JavaScript file was read, and every page was loaded in Chromium. All 15 scripts load in the right order. No two scripts declare the same global name. With the app's own server, every button, example chip, form and navigation link worked, and the console showed no errors at 1280 px or 360 px.

The real failures depend on how NetSafe is started.

## Checked and found working (no change needed)

- **Phase 2, URL analyzer:** `url-ui.js` calls `NetSafeUrl.analyzeUrl` from `url.js`. Script order is correct. Clicking "Check link" and pressing Enter both work. Results show the risk level, link parts, warnings (what we noticed, why it matters, what could happen, what to do), what was not checked and limitations. The link rated Low says "That does not make the site safe" and is never called safe. Cases tested: HTTPS, HTTP, IP v4/v6, private IP, hex IP, shorteners, brand in a subdomain, `@` trick, punycode, mixed alphabets, encoded host, unusual port, redirect parameter, risky ending, `javascript:` and `data:`, spaces, `ftp:`.
- **Phase 3, messages:** examples, highlighting, sender checks, errors and Clear all work.
- **Phase 4, password and crypto lab:** live strength estimate, show/hide, reuse box, Caesar encrypt/decrypt/brute force, AES-256-GCM (PBKDF2, 600,000 rounds) and SHA-256 all use the real Web Crypto API. A wrong passphrase and tampering are both refused.
- **Phase 5, Wi-Fi:** validation, contradictions, sharing question, scoring, floors and ceilings, and Reset all work.
- **Phase 6, overview:** statuses, plan, report download, print and Clear all work. Nothing is stored.
- **Phase 7, reports and docs:** the `.txt` report downloads and holds no typed input.
- **Python:** not required. `serve.py` is an optional local server (standard library only). The Python tests cover only that server and drive the browser. No backend was added.
